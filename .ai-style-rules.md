# MySite inherited implementation rules

Commit fingerprint: `9c3021eca021a106852e4be8005cc0c94918810b`

Scan tier: medium (74 source files). These rules preserve the existing hand-built visual identity while keeping the locale-first Astro architecture replaceable through centralized themes.

## Golden Files

- `src/layouts/BaseLayout.astro` — page shell owns SEO, shared navigation, locale metadata, footer, and global styles; page components supply content and composition.
- `src/config/routes.ts` — the only source of route and locale URL construction. Components must use its helpers instead of assembling paths.
- `src/content/pages.ts` and `src/content/pages/{locale}/` — localized content is validated and independent from layout code.
- `src/components/ui/` — shared primitives remain presentation-focused and accept composition through props/slots.
- Legacy visual source at commit `96fc66c`: `sites/hub/index.html`, `sites/hub/en/index.html`, `app/globals.css`, and `shared/ecosystem-nav.css` — authoritative Home geometry, hierarchy, colors, background, type scale, and responsive behavior.
- `docs/baseline-screenshots/home-{ru,en}-{desktop,tablet,mobile}.png` and `home-release-baselines.json` — the sole release baselines for Home, including capture metadata and SHA-256 integrity checks.
- `docs/baseline-screenshots/home-{desktop,tablet,mobile}.jpg` — historical migration evidence only; it is not a release gate.
- `tests/content-browser.mjs` — explicit route/status/media/overflow assertions with fail-fast cleanup.

## Naming & State-Control Rules

- Astro files keep imports and typed `Props` in frontmatter, derive values once, then render declarative markup.
- Shared route and locale state uses the types and helpers from `src/config/routes.ts`.
- Page copy and locale variants stay in content sources; templates do not branch on duplicated prose.
- Design values use semantic custom properties. Fonts, palette, background assets, radii, shadows, spacing, and type scale must be replaceable in one theme layer.
- Visual variants use explicit page/component classes; global element rules must not silently alter unrelated pages.
- Browser checks fail on missing baselines, unexpected network/console errors, horizontal overflow, broken locale navigation, or layout differences outside the accepted tolerance.
- Build and content lookup failures throw descriptive errors; tests use strict assertions and close browser/server resources in `finally` blocks.

## DONTs

- Do not redesign a legacy screen while migrating its framework, routes, or content model.
- Do not treat baseline screenshots as optional documentation; they are release-blocking acceptance evidence.
- Do not replace the legacy Home with a generic `page-hero`, generic global `h1`, or unrelated design-system showcase.
- Do not hard-code palette, fonts, background-image URLs, radii, or major spacing independently in page components.
- Do not construct locale or section URLs manually in components.
- Do not share new global selectors without proving no visual regression on untouched routes.
- Do not report visual PASS from HTTP status, Core Web Vitals, DOM presence, or overflow checks alone.
- Do not deploy Home to production before RU/EN desktop/tablet/mobile staging screenshots are reviewed and explicitly accepted by the owner.
